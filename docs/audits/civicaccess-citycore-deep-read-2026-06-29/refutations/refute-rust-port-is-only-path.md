# Refutation lens: refute-rust-port-is-only-path (2026-06-29 deep-read)

**Claim**:

The only way to make CivicAccess functional in the shipping desktop is to port its logic into desktop/src-tauri/src/workflows.rs (Rust) AND add UI panels in desktop/src/main.js, mirroring the civicnotice integration pattern.

**Refuted**:

True

**Reason**:

The claim is refuted because CivicAccess already exists as a complete, tested FastAPI app (~1900 lines, 18 routes, 42 tests, write-token guard, persisted reviews + atomic audit, dialect-portable DB selection, HTML staff/public UIs at /civicaccess and /civicaccess/staff). Reimplementing all that logic in Rust the way civicnotice did would discard a working module — it is the maximum-work path, not the only one. The civicnotice precedent is itself an unforced choice: notice ships a FastAPI server too, and Rust just shadows it. Several lazier paths exist where the shipping desktop becomes a thin host for the FastAPI app the team already shipped: spawn it as a 6th supervisor service and point a WebView at its /civicaccess pages, proxy a /civicaccess path prefix through Rust to an in-process app instance, or mount it as a sub-app under the existing python-services HTTP server on 127.0.0.1:15480. Each of these requires far less code than porting workflows.rs handlers, and the supervisor scaffolding (CIVICACCESS_TRUSTED_WRITE_TOKEN injection, optional /health entry, schema bootstrap, payload bundling, clerk-role grant, exports-folder mapping) is ALREADY in place from Phase B — it was built precisely for the FastAPI app to be reached, not for a Rust reimplementation.

**Alternatives**:

- ALT 1 — Spawn civicaccess uvicorn as a 6th supervisor service + open a WebView/external link to http://127.0.0.1:8060/civicaccess/staff. Code locations: (a) desktop/runtime/windows-local-runtime.json — add one service block mirroring the existing python-services entry but invoking `runtime/python/python.exe -m uvicorn civicaccess.main:app --host 127.0.0.1 --port 8060` with HTTP health on /health (default_port 8060 is already declared in installer/modules.json:557-637). (b) desktop/src-tauri/src/supervisor.rs — no code change; the existing supervisor loop reads windows-local-runtime.json via include_str! and the CIVICACCESS_TRUSTED_WRITE_TOKEN env injection at supervisor.rs:2043-2048 already covers `service.binary.ends_with('python.exe')`, so the token is auto-injected into the new process. (c) desktop/src/main.js — add a minimal nav chip `{id:'access', label:'Accessibility'}` plus a renderAccessWorkflow() that emits `<iframe src='http://127.0.0.1:8060/civicaccess/staff'>` (or for the operator surface, an `<a>` that triggers Tauri's shell.open to the URL). NO city_work_action arm needed, NO workflows.rs handler needed. Risks: (i) WebView2 needs to allow http://127.0.0.1 origin — already allowed for the supervisor /health probe so this is fine. (ii) Staff write-token paste flow already exists in civicaccess's own /civicaccess/staff page (lives in sessionStorage per main.py:162-167) — no desktop wiring needed. (iii) Port 8060 must not collide — the supervisor port set today is 15432/15480/15434 + worker so 8060 is free. Prior art: civiccore.tasks.worker is already spawned as a long-running python service via the same supervisor mechanism (windows-local-runtime.json:62-63), proving the pattern. Effort: roughly 1 JSON block + 1 nav entry + 1 iframe panel ≈ 30 lines total.
- ALT 2 — Mount civicaccess as a sub-app on the existing python-services HTTP server (port 15480) and reach it from main.js via `fetch('http://127.0.0.1:15480/civicaccess/...')`. Code locations: (a) desktop/runtime/python-services/civicsuite_runtime/services.py — services.py already imports civicaccess.main for /health; replace the stdlib ThreadingHTTPServer (services.py:184-189) with a tiny FastAPI/uvicorn app that mounts the civicaccess app via `app.mount('/civicaccess', civicaccess.main.app)` and exposes the existing `/health` + `/modules` routes alongside. (b) desktop/src/main.js — add a nav entry and a renderAccessWorkflow() that either iframes `http://127.0.0.1:15480/civicaccess/staff` or, for a closer UI feel, calls the JSON endpoints directly with fetch. No supervisor changes — same process, same port, same lifecycle. Risks: (i) The existing /health server is stdlib-only — switching to uvicorn adds a dependency on having uvicorn in the bundled Python (it already is, since civicaccess depends on it). (ii) Path collisions are trivially avoided by mounting under /civicaccess. (iii) The trusted-write-token gate works unchanged because the env var is already injected. Prior art: civiccore.llm.registry.router is an APIRouter explicitly designed to be mounted by a host app — same pattern. Effort: roughly 15 lines in services.py + 1 nav entry + 1 panel.
- ALT 3 — Add a thin Rust proxy in supervisor.rs (or a new tiny module) that forwards any `/civicaccess/*` or `/api/v1/civicaccess/*` request to an in-process uvicorn instance of civicaccess.main:app started inside the python-services process. Code locations: (a) services.py spawns uvicorn for civicaccess on an arbitrary localhost port (say 15485) in a background thread alongside the /health server. (b) desktop/src-tauri/src/supervisor.rs — add a small reqwest-based proxy handler bound to a Tauri-internal route or expose via a new Tauri command `civicaccess_proxy(method, path, body, headers) -> Response`. (c) desktop/src/main.js calls that command. Risks: introduces reqwest (currently a transitive Cargo.lock-only dep — would need to be moved to direct dependency), adds proxy serialization overhead, and is strictly more work than ALT 1/2. Useful only if the team insists on routing everything through the existing Tauri IPC contract rather than letting the WebView talk to 127.0.0.1 directly. Effort: ~80 lines.
- ALT 4 — Use Tauri's external-link / shell.open against the in-process app surface. Code locations: (a) Same supervisor service as ALT 1 (or sub-app mount as ALT 2). (b) desktop/src/main.js — add a single nav entry whose handler calls `await invoke('open_external', { url: 'http://127.0.0.1:8060/civicaccess/staff' })` using Tauri's shell plugin to open in the system browser, OR uses tauri::WebviewWindow::builder to open a child WebView. Risks: opening in system browser breaks the single-app feel; child WebView is cleaner. Prior art: the civicaccess /civicaccess/staff page is explicitly designed to be loaded in a browser-like surface (main.py:160-167 — has its own write-token paste-and-store flow). Effort: ~5 lines for the system-browser variant, ~25 for a child WebView. This is essentially ALT 1 with a system-browser fallback for users on machines where WebView2 is degraded.
- ALT 5 — Embed an iframe of the staff page inside a single renderAccessWorkflow() panel without spawning anything new — civicaccess.main.app gets started inside the existing python-services process and serves /civicaccess/* on a uvicorn the services.py boot already starts (as in ALT 2). Then main.js renders one HTML element: `<iframe src='/civicaccess/staff' style='width:100%;height:100%'>` if the Tauri shell can proxy to 127.0.0.1:15480, or a hardcoded `http://127.0.0.1:15480/civicaccess/staff`. Risks: WebView2 mixed-context loading of localhost iframes works in current Tauri (the supervisor already polls 127.0.0.1:15480 from the WebView). Effort: ~10 lines in services.py + 1 iframe in main.js. THE LAZIEST viable path — reuses the existing FastAPI app, the existing port, the existing token injection, the existing staff UI, and the existing schema bootstrap. ZERO Rust changes.
- ALT 6 — Don't ship civicaccess in the desktop at all until v1.0.2; document it as 'browser-only beta — run `pip install civicaccess && uvicorn civicaccess.main:app` and visit http://127.0.0.1:8060/civicaccess'. Code locations: no code change. Roll back the Phase C truth flips (PR #214) so STATUS/README/USER-MANUAL say 5 not 6 city-core modules in the v1.0.1 MSI. Risks: messaging churn — but the existing STATUS.md already includes the caveat 'the published v1.0.1 MSI bundles the first 5 city-core modules; the six-module MSI is the next build'. Effort: a few-line docs revert. Strictly the smallest diff and honest about today's reality.
