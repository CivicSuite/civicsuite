**Notable findings**:

- V1.7.1 (2026-05-23) moved document parsing, chunking, embeddings, and pgvector ingest to shared civiccore.ingest pipeline; Records-AI retains only Celery tasks, scheduling, sync orchestration, and cron helpers. This split was intentional to unify ingestion across modules (Records, Clerk, Code, Access share the same pipeline).
- V1.7.3 (2026-05-24) added wheel and sdist release assets for pip consumers, but city-core installer still vendors source; no runtime behavior change.
- First-admin account created on startup is marked must_change_password=True; staff/admin routes return 403 until password rotated via /users/me (security gate added in unreleased version).
- Portal mode (public/private) is a deployment-wide setting gating resident self-registration and records-request submission; UI branches on /config/portal-mode endpoint result.
- Exemption detection has two tiers: Tier 1 uses regex + PII detection (SSN, credit card, phone, email, bank account, state DL), Tier 2 offers optional LLM secondary review; all flags require human confirmation before release.
- Circuit breaker implemented on data source syncs: 5 consecutive full-run failures trigger sync_paused state; admin can manually unpause after reviewing failures.
- Connector framework is standardized (authenticate/discover/fetch/health_check protocol); four types implemented (file_system, manual_drop, rest_api, odbc), with IMAP/SMB/NFS/SharePoint on roadmap.
- Audit logs are hash-chained for compliance; 1095-day retention default (3 years); /audit/verify endpoint can verify chain integrity.
- Department scoping reduces visibility: staff see only requests assigned to their department; admin sees all.
- Notifications use SMTP+Celery beat (60s tick); template-based, not yet wired to status transitions (queued feature).
