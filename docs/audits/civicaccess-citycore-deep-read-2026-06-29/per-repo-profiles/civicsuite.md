**Notable findings**:

- This repo IS the umbrella (civicsuite), NOT a standalone module. It defines the Windows-Local installer entrypoint (desktop/), module registry (installer/modules.json), verification gates (scripts/verify-suite-state.py), and governance (CHANGELOG, STATUS, FAQ, architecture docs).
- Module source code does NOT live here; modules are separate GitHub repos (CivicSuite/civicrecords-ai, /civicclerk, /civiccode, /civicnotice, /civicaccess) pinned by source_commit in installer/modules.json. The umbrella orchestrates, does not contain module implementations.
- Windows-Local profile is explicitly no Docker, no WSL, no terminal: Tauri/WebView2 desktop shell wraps portable PostgreSQL 17 + pgvector, bundled CPython (3.12), Ollama (local LLM), and a PostgreSQL-backed CivicCore task queue. All city-core modules run as Python library imports in a single http://127.0.0.1:15480 service health bridge, not as separate HTTP servers.
- Release versioning is decoupled: umbrella docs document city-core module versions (civicrecords-ai v1.7.3, civicclerk v1.0.4, civiccode v1.0.8, civicnotice v0.2.0, civicaccess v0.4.0), but the umbrella itself is never versioned. The Windows-Local MSI is versioned (v1.0.1) but that's the desktop shell version, not umbrella version.
- Current status is 'GA candidate / public beta' (2026-06-28): unsigned MSI, zero open Blocker/Critical findings after two audit passes, awaiting Authenticode signing via SignPath Foundation. City-core is beta-ready, not public-use/production-ready.
- CivicAccess was demoted from city-core (2026-05-23 NEEDS-WORK), then re-probed and promoted back (2026-06-29) as the sixth city-core module. Every hard-coded gate (module count, test assertions, verify scripts) was updated in a lockstep changeset.
- Desktop consumption model (Tauri/WebView2): no outbound module HTTP forwarding observed; modules invoked as Python library imports + task-queue async dispatch. Frontend (desktop/src/main.js) uses Tauri IPC (invoke()) to call Rust command handlers; Rust dispatches to supervisor (manage services), workflows (city-work), auth (sign-in), model (LLM registry).
- Test coverage is thin umbrella-level only (contract test, module manifest test, state verification). Module tests live in per-module repos. Desktop has static smoke + XSS + Playwright browser tests but no unit test suite for Rust code or supervision logic.
