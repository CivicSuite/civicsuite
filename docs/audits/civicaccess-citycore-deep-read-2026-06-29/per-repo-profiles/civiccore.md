**Notable findings**:

- civiccore is non-selectable and required: all city-core deployments must have it regardless of module profile
- No HTTP server startup code: civiccore ships the router but consumers must mount it on their own FastAPI app with dependency override
- Task queue requires explicit env var CIVICCORE_TASK_HANDLER_MODULES to load handler modules; modules must register via decorator at import time
- Three built-in LLM providers (Ollama/OpenAI/Anthropic) registered via decorator side effects at import; third-party providers can register without modifying civiccore source
- Platform contracts explicitly deferred: civiccore.catalog, civiccore.exemptions (50-state FOIA engine), civiccore.scaffold remain placeholder packages per ADRs
- Document ingestion uses local Ollama only; no cloud embeddings vendor lock-in; uses pgvector for persistence
- Auth helpers support mixed public/staff routes: resolve_optional_bearer_roles returns None for anonymous callers, letting public endpoints stay public until caller presents bearer token
- Migration ordering: civiccore runs before all module migrations; migration runner in desktop enforces this order via _run_alembic() calls in fixed sequence
- Desktop dependency structure: Python services host → civiccore contract validation → task queue worker → Postgres (civiccore_local_tasks table) → module task handlers
- ci Version 1.0 released and marked 'provisional recovery line' due to audit security hardening; v1.2.0 is current productization line for city-core
