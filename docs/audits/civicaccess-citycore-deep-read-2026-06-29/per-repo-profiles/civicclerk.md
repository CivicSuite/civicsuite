**Notable findings**:

- CivicClerk is the largest single city-core module: 81 HTTP routes across 50 source modules (models.py, agenda_lifecycle.py, meeting_lifecycle.py, notice_checklist.py, packet_assembly.py, motion_vote.py, minutes.py, public_archive.py, vendor_live_sync.py, oidc_auth.py, connectors.py, etc.); 395 pytest functions across 58 test files. Complexity rivals a small SaaS product.
- Database persistence is modular: Each domain (agenda_item, meeting, packet_assembly, notice_checklist, motion_vote, minutes_draft, public_archive, public_comment, vendor_sync) can opt into PostgreSQL via separate DB URL env vars, with in-memory fallback. This allows pilot deployments to work without a database, then harden with real DB on upgrade.
- Staff auth is production-ready: Five modes (protected default, open, bearer token, OIDC with browser session, trusted-header reverse proxy) all implemented. OIDC browser session handling is module-local because CivicCore hasn't shipped that yet (ADR-0009); marked as extraction candidate for future CivicCore release.
- Vendor sync is supervised: Circuit-breaker pattern (five consecutive failures -> open), persisted delta cursor, no-network rehearsal helpers (check_vendor_live_sync_readiness.py). Desktop can enable scheduled pulls via CIVICCLERK_VENDOR_NETWORK_SYNC_SCHEDULE_ENABLED, but defaults to local-first connector imports only.
- Public archive has closed-session safeguards: Leak prevention for counts, suggestions, error messages. /public endpoints require bearer role check for closed-session visibility. Desktop search must filter staff-only records before displaying resident portal.
- Prompt library is YAML-based and versioned: All AI assistance goes through civiccore.llm.resolve_template with consumer_app=civicclerk. Offline eval harness runs with CIVICCORE_LLM_PROVIDER=ollama and NO_NETWORK=1, covering policy phrases, public approval gates, and input mutation stability.
- Minutes drafts are citation-gated: No auto-posting of AI-drafted output. Every sentence must cite a source (packet item, staff report, transcript). Human approval required before posting to public archive. Matches legal record requirements for municipal minutes.
- Release recovery posture: v1.0.4 is marked 'provisional' until gates pass: local backend tests, frontend unit tests, real Playwright user-flow tests, WSL install proof, release consistency checks, secret/security scans, docs-source parity. Live-wire integration claims now distinguished from mock validation.
- Desktop installs unsigned Windows package via Inno Setup: No code signing because CivicSuite is small free open-source; Windows SmartScreen will warn; users expect and accept 'More info' + 'Run anyway'. Installer wraps Docker Desktop check + PostgreSQL 17 portability + Ollama runtime setup + seeded demo data.
- Docker Compose stack includes Redis 7.2 + Celery + Celery Beat: Background tasks include optional scheduled connector imports (local file-drop sync) and optional scheduled vendor-network pulls (gated by two separate enable flags for safety). Neither runs by default.
- Module is integrated into desktop UI at multiple layers: (1) Tauri backend calls civicclerk HTTP to record audit entries; (2) React staff shell embedded in Docker/nginx at /staff; (3) Resident public portal at /public; (4) Search crosses modules but must filter closed-session content per role.
