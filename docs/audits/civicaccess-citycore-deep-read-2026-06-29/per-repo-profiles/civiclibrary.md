**Notable findings**:

- CivicLibrary is deterministic and offline-first: all endpoints return hardcoded or derived responses without calling external LLMs or remote services. See answer_policy_question (policy.py line 24-36), answer_program_question (programs.py line 21-26), search_collection_metadata (reference.py line 23-33), draft_collection_guidance (collection.py line 14-23) — all return deterministic payloads.
- Optional SQLAlchemy persistence is cleanly decoupled: workpaper storage only activates if CIVICLIBRARY_WORKPAPER_DB_URL environment variable is set. Without it, deterministic responses are returned and answer_id/guidance_id are None (main.py lines 109-117, 137-145). Fallback error messages are actionable (main.py lines 123, 151).
- Patron record privacy is enforced at the reference layer: search_collection_metadata explicitly filters patron_record=True items (reference.py lines 23-28) and sets patron_records_excluded flag in response. Boundary notes in every endpoint reinforce: 'No patron record access' (public_ui.py line 33), 'Patron borrowing...excluded' (reference.py line 30-31), 'does not access patron records' (policy.py line 35).
- No active desktop integration: Module is registered in installer but not wired into the city-core profile or desktop navigation. It remains in full-suite (which is disabled). This means CivicAccess must follow the same path: register in installer with proof gates, but actual desktop UI routing/wiring will come in a subsequent integration phase.
- Tests verify honest boundaries: test_root_reports_honest_current_state (test_runtime_foundation.py) asserts that the root endpoint explicitly states 'patron record access' is 'not implemented yet' (line 14-15). This pattern of shipping honest scope boundaries is core to CivicLibrary's design.
