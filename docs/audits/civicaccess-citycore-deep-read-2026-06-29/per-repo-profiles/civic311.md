**Notable findings**:

- Civic311 is a pre-integration module: fully functional but NOT bundled in the desktop payloads and NOT exposed in the desktop UI navigation. It exists as a registered module spec in installer/modules.json but awaits runtime wiring.
- Module uses deterministic triage (keyword matching) not LLMs; all logic is staff-supervised with built-in disclaimers on every response.
- Optional persistence via CIVIC311_REQUEST_DB_URL environment variable; when not set, intake/triage become stateless and retrieval endpoints return 503 with actionable fix messages.
- Public UI at /civic311 is intentionally honest about boundaries (explicitly states 'does not create official work orders' and 'does not replace system of record').
- Dependencies are minimal: FastAPI, SQLAlchemy, UVicorn, CivicCore only; no LLM calls, no external service integrations.
