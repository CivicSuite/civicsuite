**Module-6 relevance**:

CivicNotice is the reference integration precedent for CivicAccess (Phase B/C/D). Patterns: (1) Optional persistent workpapers: SQLAlchemy-backed postgres tables (notice_registry_records, deadline_plan_records, publication_proof_records) in civicnotice schema, UUID primary keys, JSON array/object columns for structured metadata, optional via env var CIVICNOTICE_WORKPAPER_DB_URL. (2) Deterministic stateless fallback: without DB, POST registry/deadline return transient payloads, GET return 503; enables offline development and clear boundary. (3) Trusted write guard: persistence writes require X-CivicNotice-Write-Token header + CIVICNOTICE_TRUSTED_WRITE_TOKEN env var (minimal local-mode guard, not production identity). (4) Desktop wiring pattern: module imported in services.py for /health checks, FastAPI app runs as bundled python service on assigned port (8066), workflows.rs handles action dispatch (civicnotice-* action names), main.js renders workflow UI buttons and fetch calls to localhost:PORT. (5) Shared disclaimer pattern: all outputs carry DISCLAIMER tuple stating staff remain responsible for legal sufficiency, official record, publication approvals; honest unshipped-boundary copy in / and /health. (6) Notice type rule packs: RULE_PACKS dict keyed by notice_type (planning hearing, bid notice, vacancy notice, etc.), each NoticeRule defines minimum_lead_days, required_publications, required_channels, required_content, emergency_path_allowed; used by check_statutory_notice_requirements() for deterministic staff-review flags. (7) Archive packet handoff: build_notice_archive_packet() returns handoff_targets tuple (civicclerk|civicprocure|civicboards|manual staff archive, civicrecords) based on source_module; models cross-module record routing.
