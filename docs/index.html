CivicSuite Windows Local

A local-first municipal operations suite that runs on the city's own computer.

CivicSuite Windows Local is an offline, sovereignly deployable operations suite for small cities. It installs as one Windows desktop app — bundling its own database and a local AI model — so a clerk can do real work with no cloud account, no telemetry, and no per-seat pricing. The current build is v1.0.2, a GA-candidate public beta.

  • Local firstNo cloud requirement, no telemetry, no per-seat pricing. Data stays on the city's machine.
  • One-app installA single Windows installer sets up everything — database, services, and the local AI model. No Docker, WSL, or terminal.
  • Honest about statusA GA-candidate beta. The one remaining gate to General Availability is a code-signing certificate.

Status today

Status snapshot: 2026-07-02. Current build: CivicSuite Windows Local v1.0.2 GA candidate · public beta (predecessor: v1.0.1).

What "GA candidate, public beta" means. The build is feature-complete for the city-core profile and was validated end to end on a clean Windows machine. The one remaining gate to General Availability is an Authenticode code-signing certificate (in progress). Until then the MSI ships unsigned: Windows SmartScreen shows "Unknown Publisher" — verify the published SHA-256, then choose More info → Run anyway. This is not a public-use, city-ready, procurement, production, or full-suite promotion claim.

The city-core profile

CivicSuite Windows Local ships the city-core profile: six modules. CivicCore is the shared platform every module depends on; it is always installed and cannot be deselected. All six are bundled in the v1.0.2 desktop app.

ModuleVersionWhat it does
CivicCorev1.2.0Shared platform: identity, audit, retention, the local task queue/worker, and document ingestion. Every module depends on it; it depends on none.
CivicRecords AIv1.7.3Public records / FOIA request intake, search, and AI-assisted response drafting.
CivicClerkv1.0.4Meetings, agendas, packets, minutes, and votes.
CivicCodev1.0.8Municipal code: searchable ordinances with AI-assisted guidance.
CivicNoticev0.2.0Public-notice creation and publishing workflow.
CivicAccessv0.4.0Accessibility workflows and records-ready export. Its on-screen Accessibility tab, with three local-AI features, is the headline addition in v1.0.2.

CivicZone, CivicPlan, CivicPermit, and CivicInspect remain queued Tier 2 modules and are not part of city-core. The rest of the wider catalog is foundation-tier (schemas and specs), not city-ready product.

New in v1.0.2

The CivicAccess Accessibility tab

v1.0.2 adds the on-screen Accessibility workflow tab to the desktop app. Alongside deterministic checklist tools (form plans, publishing workflow, ADA Title II, tagged-PDF expectations), it introduces three features that run on the bundled local Gemma model:

  • Plain-Language Rewrite — drafts a plain-language version of text a clerk enters.
  • Multilingual Variant — drafts a translation of the entered text into any target language.
  • Accessibility Review — runs deterministic WCAG rule checks and stores a short model-drafted remediation analysis alongside them.

How the AI is scoped — read this. Each AI feature is dual-path: when the local model isn't ready, it falls back to a deterministic result clearly labeled "AI engine not ready." Every AI output is labeled a draft requiring human review. Translations must go to a qualified human translator before public use. A saved Accessibility Review is advisory clerk support, not a certified accessibility audit — the records-bearing status derives only from the deterministic rule checks; the AI never adds, removes, or reclassifies a finding.

Clean-machine fix (bundled VC++ runtime)

v1.0.2 also fixes a start-up failure on a fresh Windows PC. The bundled PostgreSQL binaries depend on the Microsoft Visual C++ runtime, which a clean machine may not have. v1.0.2 bundles the required VC++ runtime DLLs next to the database binaries, so PostgreSQL — and everything that depends on it — starts on a fresh Windows computer with no separate redistributable install.

For clerks and decision-makers

You do not need an IT department to use this. CivicSuite installs the way any Windows program does — one installer — and then it just runs on that computer. There is no website to log into, no monthly subscription, and nothing about your city's records is sent anywhere off the machine.

What that buys a small city:

  • Your data stays yours. Records, meeting minutes, notices, and requests live on your own computer. There is no cloud service that could go dark, change its price, or be subpoenaed out from under you.
  • No recurring bill. No per-seat licensing and no per-user fees. The software runs on hardware you already own.
  • Works offline. The AI features run from a model bundled inside the app on your machine — not a paid API — so they keep working with no internet connection.
  • Everyday municipal work in one place. Public-records requests, meetings and minutes, municipal code, public notices, and accessibility support — six connected modules that share one identity, audit trail, and search.
  • AI that stays in its lane. The AI drafts and suggests; a person always reviews and decides. Plain-language rewrites and translations are starting points for a qualified human, not finished official output.

Recommended hardware: 32 GB of RAM is recommended (16 GB is a workable minimum), about 15 GB of free disk space, and 64-bit Windows 10 or 11 with WebView2. Most office desktops bought in the last few years meet this.

For IT and technical evaluators

CivicSuite Windows Local is a single Tauri/WebView2 desktop application that bundles its full runtime. There is no external service dependency, no container runtime, and no developer tooling required on the target machine. Everything below runs as local processes supervised by the desktop shell.

Bundled components

  • Desktop shell: Tauri / WebView2. One MSI installs the app and its full runtime; the end-user clerk path needs no Docker, WSL, terminal, browser URL, or developer tooling.
  • Database: portable PostgreSQL 17 with pgvector for vector search. v1.0.2 stages the Microsoft Visual C++ runtime DLLs next to the PostgreSQL binaries so the data store starts on a clean Windows machine.
  • Services: embedded CPython city services with a PostgreSQL-backed local task queue and worker — the queue and workers are the Windows-local profile, replacing the server-profile Redis/Celery stack.
  • Local AI: Ollama serving a pinned local Gemma model, registered through an explicit download / checksum / runtime step on first run. Inference is on-device; the four AI-capable areas (CivicClerk minutes, CivicRecords response, CivicCode guidance, and the three CivicAccess features) share one local-generation path.
  • Local operations: local file storage, local backup/restore, and repair/support-bundle flows. No telemetry, no per-seat licensing.

Dependency and trust

The dependency rule is one-directional: modules depend on CivicCore; CivicCore never depends on modules. The MSI is unsigned during the beta — the trust path is the published MSI SHA-256 plus the per-module source_commit pins (see PROVENANCE.md and CODE_SIGNING_POLICY.md). Verify the checksum before running, then More info → Run anyway past SmartScreen. For the full data-flow rules see ARCHITECTURE.md.
