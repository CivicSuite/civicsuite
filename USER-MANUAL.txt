CivicSuite - User Manual
========================

This is the orientation manual for the CivicSuite umbrella repo. It is written
in three parts:

1. For municipal decision-makers
2. For developers and IT staff
3. Architecture reference

Part 1 - For municipal decision-makers
--------------------------------------

CivicSuite is an open-source municipal product family. It is not one giant
program. It is a collection of modules that a city can install one at a time,
on its own hardware, on its own schedule.

Current maturity snapshot as of 2026-05-04:

- `civicrecords-ai v1.4.10`: shipping flagship product
- `civiccore v0.22.0`: shared platform package
- `civicclerk v0.1.20`: productizing second-product candidate
- `civiccode v0.1.15`: active municipal-code productization lane with durable
  section lifecycle, popular-question, staff-note, plain-language summary,
  CivicClerk handoff, handoff audit-event, and related-material discovery aids
- CivicRegWatch and CivicAPI: planned modules with implementation specs
- Remaining catalog modules: foundation tier

The authoritative module-to-platform version truth lives in:

- `docs/compatibility/index.md`

What this means for a city:

- no vendor lock-in
- no mandatory cloud dependency
- no per-seat billing
- evaluate one module at a time
- the city still owns hosting and operations
- Windows installers are unsigned during the developer process unless a module
  explicitly says otherwise, so first installs can show SmartScreen or
  untrusted-publisher warnings until a certificate is available.

Part 2 - For developers and IT staff
------------------------------------

The `civicsuite` repo is documentation-first and coordination-first. It
contains:

- `CHARTER.md`
- `SUCCESSION.md`
- `docs/compatibility/index.md`
- `docs/roadmap/index.md`
- `docs/roadmap/shared-extraction-consumer-rollout.md`
- suite specs, governance docs, and ADRs

It does not contain the runtime code for individual products.

Core dependency rule:

- modules depend on `civiccore`
- `civiccore` never depends on modules

`civiccore` is consumed as a released dependency, either as a published package
or as a GitHub release wheel, depending on the current release path. Check the
compatibility matrix for exact pairings.

Release coordination:

1. `civiccore` ships first.
2. consumer modules adopt the change through the standard rollout playbook.
3. the compatibility matrix is updated.
4. suite-facing docs are updated when public state changes.

Part 3 - Architecture reference
-------------------------------

Top-level topology:

- `civicsuite`: umbrella docs, roadmap, governance, compatibility
- `civiccore`: shared platform package
- `civicrecords-ai`: shipping flagship product
- `civicclerk`: productizing second-product candidate
- `civicregwatch`: planned federal regulatory intelligence module
- `civicapi`: planned public read-only data gateway module
- remaining catalog repos: foundation tier

Continuity baseline:

- `SUCCESSION.md`

Roadmap:

- `docs/roadmap/index.md`

When something goes wrong
-------------------------

- install issues: module repo `README.md` and `CONTRIBUTING.md`
- version mismatch: `docs/compatibility/index.md`
- bug routing: `CONTRIBUTING.md`
- security issue: `SECURITY.md`
- support question: `SUPPORT.md`
